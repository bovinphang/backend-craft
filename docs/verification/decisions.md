# 实施决策

- Ruling: 沿用已批准计划指定的当前 checkout 与功能分支，不新建 worktree — 上级指令优先复用当前 checkout；代价是变更直接显示在当前目录。

- Ruling: 不调用自动提交的技能脚本；使用逐任务 brief 和本账本记录等效步骤/测试证据 — 用户尚未授权本项目 Git 提交；代价是最终审阅须包含未跟踪文件。

- Ruling: 公开包与 F 旧快照六文件仅换行不同，但仍保留精确摘要保护；任务 13 最小同步 F 生成资源和依赖锁，不改前端业务代码 — 真实共存不能基于旧开发 tarball；代价是最终工作区含一组前端生成内容修复，须单独交代。

- Ruling: B 使用 text=auto eol=lf 稳定 Git 检出字节；前端修复任务也须为生成锁资源指定 LF — 精确内容摘要是跨平台契约；代价是项目统一文本换行，但二进制仍按 Git 自动识别保留。

- Ruling: inspectProject 传入 taskPath 时只返回最近项目，未传时列出全部 — 防止验证时执行无关兄弟工程；代价是全仓库报告需省略 taskPath，符合设计的任务局部上下文要求。

- Ruling: 有 Java wrapper 的工程默认不调用 wrapper 或以全局工具替代；需要显式本地准备配置 — 离线构建参数不阻止 wrapper 自身下载；代价是 wrapper-only 项目初次验证需用户指定已准备的入口。

- Ruling: Integration 未启用时计划保留带 skipReason 的阶段，必需阶段跳过在执行结果中不可报成功 — 保留审计痕迹；代价是内部 StageSpec 增加可选 skipReason、ValidationPlan 增加 warnings，JSON 输出需在 CLI 单独脱敏 env 值。

- Ruling: 仓库已有任务优先目前支持显式 Makefile 质量目标及语言构建器固有入口，不执行未知格式 shell 配置；复杂工作流通过 .backend-craft.json 明确 — 防止随意猜命令；代价是特殊任务器需显式配置。

- Ruling: 使用官方 cross-spawn 7.0.6 的 Windows 参数转义并以真实 .cmd 测试验证，不自写 shell quoting — 原生 Node 不支持直接 .cmd；代价是新增小型运行依赖及类型包。

- Ruling: 标准测试需要正测试计数、Go 事件或新鲜 JUnit 报告；自定义 harness 可输出 backend-craft:tests=N 正计数标记 — exit=0 不足以证明测试运行；代价是无法识别的测试工具需配置可验证输出，不能冒称通过。

- Ruling: 本期 Skill 为领域参考、模式和公共方法适配，不因基线已有正确知识就虚构纪律违规；命名/发现/资源契约以静态 RED→GREEN 证明，应用场景另验，不宣称可量化提升 — 符合批准计划如实记录基线的要求；代价是本次不能提供行为改善率。

- Ruling: planSharedEntry 增加可选 previous 参数，由产品清单传入历史摘要，不能用本次期望值证明旧条目的所有权；TOML 用解析器核验并只增删严格匹配的独立标记片段，无法追加时拒绝；代价是复杂已有 TOML 表需手动整合。

- Ruling: common 1.0.1 尚未公开发布，先用本地构建包验证，最终 package/lock 回归标准精确版本，不保留 file 路径或供应链例外；公开源 frozen 安装记录为发布阻塞，不假称可安装。代价是依赖发布前不能执行干净公开源安装。

- Ruling: C/F 的生成文本固定 LF，C 工作树转换为 LF 后生成 1.0.1，避免 Git 检出改变锁字节；F 只同步依赖、公共生成文件、索引和属性，不改业务实现。

- Ruling: 安装规划重复规范化旧清单路径产生二次复杂度，改为会话开始一次校验和索引，写入按规范路径索引匹配，保留所有边界校验；同用例耗时从约 20 秒降至数秒，没有削弱所有权判断。

- Ruling: 已安装非默认语言在省略 --lang 时沿用原清单，不擅自切换语言；代价是改语言必须明确传 --lang，与用户对更新的正常预期一致。

- Ruling: 未发布 1.0.1 触发 pnpm 前置供应链策略拒绝，使用已安装本地 eslint/tsc/tsx 执行 package.json 同一脚本进行验证，不声称 pnpm 入口通过；代价是公开安装和原命令验收必须等待正式发布及策略窗口。

- Final: minor (deferred): M1 inspect 目前只报告工程证据，工具可用性请用 validate --dry-run；后续可增加严格只读工具状态探测，本期不声称已交付该字段。

- Final: Ruling: 双原生插件 cc 发现去重不在本期范围 — 批准设计仅保证单产品原生完整性，CLI 共存不外推；代价是双原生用户需自行选择渠道避免重复。

- Final: Ruling: 不重新设计既有大型图标/图表数据业务语义 — 复用来源并验资源闭包；代价是既有数据的领域语义偏差不会被本次全量重新审定。

- Final: Ruling: 宿主实机 UI 实际启用保持 unknown — 当前证据只覆盖文件与归档，不能推断信任/刷新状态；代价是用户仍需在宿主确认启用。

- Final: Ruling: 最近工程独立配置优先工作区配置，且按其所在目录解析路径 — 防止子项目显式入口丢失或被无关根配置损坏阻断；代价是不会自动叠加根配置策略，需明确统一配置。

- Final: Ruling: 清单会话代表完整产品规划，退役本轮未再请求的未修改资源 — 更新不能继续加载已删除能力；代价是内部适配器必须每轮给出完整期望集合，不能将多次会话当增量累加。
