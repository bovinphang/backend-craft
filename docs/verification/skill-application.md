## 方式与证据

`tests/evals/scenarios.json` 定义 27 项独立任务。三组无技能代理先回答，之后三个新的独立上下文按任务加载对应 SKILL.md、专业 reference，以及四个领域流程的本地公共方法后回答。作者逐项读取原始输出，未让测试代理自评为通过。

内容创建前，27 个新入口及组合契约测试因缺失明确失败。之后按入口逐个写入并运行该入口测试，当前入口未通过不继续下一个。最终 29 项内容契约测试通过，双语共 34 个入口，元数据/关系/资源闭合及本地方法均可读取。包括工程识别和执行器的当前完整套件为 74/74，lint/typecheck 通过。

原始无技能及加载后回答位于本任务忽略目录 `.superpowers/sdd/2026-11-06-backend-craft/` 的 baseline-a/b/c.md、application-a/b/c.md；原始工具输出未删除，未编造已运行的业务测试。

## 逐组判定

| 入口组 | 已检查的应用行为 | 结论及限制 |
| --- | --- | --- |
| Rust/Go/Java/Python/C/C++ 六语言规范 | 所属子项目、既有工具链、依赖/错误边界；C cleanup 与 C++ RAII 区分；实现→测试→评审步骤 | 专业决策与文档边界一致；属于任务推演，尚未证明真实编译、数据库或 ABI 行为 |
| Rust 异步、Go 并发、Java 运行时 | 部分写入取消、句柄/关闭归属、有界并发、运行时证据与对照 | 未用无限 spawn/吞错/十倍扩容代替定位；未运行真实竞争测试或 JFR |
| Python 异步、原生内存 | 取消不等于线程停止、连接归还时点、FFI 分配配对与销毁时序 | 保留语言差异和资源责任；未宣称 sanitizer 可以证明无全部未定义行为 |
| 架构/API/数据库/事务 | 保留可行单体、幂等与兼容、分阶段迁移、局部事务与外部副作用分离 | 未承诺通用无锁 DDL、跨系统原子提交或无条件恰好一次；真实环境验证待后续任务 |

| 性能/测试策略/依赖/评审 | 同负载基线、风险矩阵、最小依赖升级、严重性与位置证据 | 未虚构改善数字、覆盖率安全性或真实行号；只读评审不直接改代码 |
| 初始化/调试/文档/重构/TDD | 保留用户规则、可证伪假设、事实源与生成边界、可逆变换、真实红绿及 NOT PROVEN | 不覆盖前端上下文、不伪造根因、不手改生成物掩盖漂移、不把事后测试冒称先测后写 |

## 不能据此推导的结论

- 基线回答本身已具备主要专业知识，未观察到需要新禁止性纪律纠正的明显违规。因此本轮证明的是入口发现、领域资料和应用边界可用，不能宣称新增 Skill 使合规率提升某个百分比。
- 三个基线代理首次读取了整个场景文件，虽然只回答各自九项且未读取任何 Skill、设计或计划，但不构成完全隔离的分组实验。后测使用独立分组输入；仍不据此作因果提升统计。
- 代理回答是参考/模式的应用，不是执行日志。六语言真实工程及实际 CLI 生命周期验证属于后续任务，届时单独记录运行工具、命令、失败与修复结果。
- 本次没有为了制造 RED 虚构代理违规；真实静态缺失契约先 RED 后 GREEN，行为推演与代码验证证据分开报告。
