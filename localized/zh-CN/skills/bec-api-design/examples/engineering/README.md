# 响应失败后的 HTTP 重放 — EP-SVC-01

本例只使用 Go >=1.20 标准库。在本目录运行 `go test -json -count=1 .`。设置 `CRAFT_ENGINEERING_DEFECTIVE=1` 移除去重并观察三项真实断言失败，设为 `0` 验证默认保护实现。产品根目录的 `pnpm run verify:engineering` 在隔离源码副本编译并运行两分支，将原始JSON测试日志与hash保存在 reports/engineering。不下载依赖；接受 `--prepare`，但标准库例无需准备依赖。

真实 httptest HTTP 客户端观察：提交后的503失败响应、同键同规范化意图复用同一回执且效果为一次、意图改变返回409、并发重复得到同一结果且只生效一次。注入的效果递增原子计数器，其观察独立于HTTP响应生成。JSON属性顺序不同不会改变解码后的业务意图，不使用任意等待控制顺序。

本例限定单进程内存，互斥保护效果/结果所有权，记录保留至测试结束。生产环境须另行设计实际的持久原子性、保留期、容量和恢复。没有数据库、消息代理、崩溃恢复或分布式恰好一次证明。测试主体回调返回合成常量，不是鉴权，也不信任角色头。状态码属于本例契约。只有已验证服务端重放契约下的同操作/同键/同意图才能在有界预算内重试；仅超时或普通5xx不允许任意重放写入。参见[本入口决策](../../references/engineering-practices.md)。
