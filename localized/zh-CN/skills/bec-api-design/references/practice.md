# 后端 API 契约

## 关键检查

1. 从实际操作、客户端、信任边界和已部署契约版本出发，区分业务未决事项与端点机制。

2. 定义校验、稳定错误、状态语义和独立于传输的业务结果；内部异常不得直接成为公共载荷。

3. 对重试明确键作用域、参数冲突、原子唯一性、处理中状态、结果重放和保留期限；POST 本身不保证幂等。

4. 谨慎增加字段，保持旧消费者可用，删除字段前定义弃用与兼容检查。

5. 列表明确稳定排序、分页上限和过滤行为；写入明确并发/版本前提，授权在服务端执行。

6. 以旧客户端契约、非法输入、并发重复请求和提交后超时验证，记录未解决兼容假设。

## 边界与案例

适用场景：
- 让创建订单重试具有幂等语义
- 兼容老客户端演进请求 schema
- 定义稳定 API 错误和校验边界
- 测试分页与并发重试契约

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
