# 缓存一致性与韧性

## 关键检查

1. 说明权威源、键归属、新鲜度目标及陈旧读取影响；权限场景可能需要拒绝不确定授权或校验版本。

2. 定义键作用域和序列化兼容性，包含租户及 schema 版本，防止不完整键造成跨租户共享。

3. 让失效与已提交变更、有界 TTL、回填/版本规则协调，说明失效事件丢失后的行为。

4. 按需采用有界请求合并、锁归属/到期和抖动；缺少完成及失败规则的锁会制造新故障。

5. 缓存故障时限制回源并定义恢复，不能为了命中率把缓存变成唯一真相。

6. 测试撤销/读取竞争、失效丢失、旧值回填、饱和与恢复，同时测延迟和源负载。

## 边界与案例

适用场景：
- 撤销权限后失效缓存
- 避免缓存击穿且不使用无界锁
- 规定陈旧数据上限及缓存降级
- 测试缓存回填与提交更新竞争

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
