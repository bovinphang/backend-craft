# 后端代码评审

## 关键检查

1. 确定 diff 范围、所属工程、契约及实际验证结果，报告风险前阅读变更代码和调用方。

2. 优先处理数据损坏、授权绕过、重复副作用、死锁/泄漏及兼容回归，再看风格。

3. 每项发现包含严重性、已核实文件/行号、触发、用户/业务影响、最小建议及回归场景。

4. 结合上下文检查事务/外部副作用、取消/所有权、查询作用域和错误映射；不报告无路径证据的假想漏洞。

5. 合并同类小问题，记录反证，区分缺少测试证据与已证明运行时缺陷。

6. 保存含发现、验证及未决问题的简洁评审报告；只读评审不改实现。

<a id="scope"></a>
## 边界与案例

适用场景：
- 审查后端 PR 的事务和重试
- 评估 diff 中租户授权与 API 兼容
- 检查并发及资源回归证据
- 输出带位置和严重性的后端发现

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
