# 数据库演进与查询设计

## 关键检查

1. 确认引擎/版本、数据规模分布、关键查询、约束及部署归属；可用时读取执行计划与锁/延迟证据。

2. 由不变量确定键、基数、可空和唯一性；ORM 映射不能代替数据库约束与查询审查。

3. 按实际谓词、排序和写入成本选取引擎支持的索引/查询变更，不把通用 online 操作宣称为无锁。

4. 分离扩展、兼容读写、有界回填、校验及旧契约移除，定义各阶段失败和暂停条件。

5. 说明回滚兼容性及新写入数据的处理；破坏性 down migration 不自动等于安全回滚。

6. 用代表性规模与权限演练，观察锁、复制延迟及错误率；自动验证不执行生产迁移。

## 边界与案例

适用场景：
- 在大表分阶段上线非空列
- 结合真实执行计划审查索引
- 设计数据回填及约束校验阶段
- 规划 schema 兼容与迁移回滚

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
