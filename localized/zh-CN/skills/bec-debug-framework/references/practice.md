# 后端诊断流程

## 关键检查

1. 应用本地公共诊断方法，选择实验前记录症状、范围、环境和近期变更。

2. 建立可证伪竞争假设，写明所需证据及各自否定条件。

3. 有界采集关联信息、池/查询/下游耗时及相关追踪，不采集凭据或原始个人载荷。

4. 复现或缩小故障，每次只改一个相关变量；同时打多个无关补丁会破坏归因。

5. 修复确认路径，再用已有语言工具测试原触发、错误恢复及邻近行为。

6. 报告事实、已否定/剩余假设、实际检查及限制；证据不足时将根因或修复结论标为 NOT PROVEN。

<a id="scope"></a>
## 边界与案例

适用场景：
- 不靠猜测排查后端间歇 500
- 比较连接池与下游超时假设
- 复现后端构建或数据故障
- 以回归证据验证最小服务修复

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
