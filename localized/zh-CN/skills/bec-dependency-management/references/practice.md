# 后端依赖变更

## 关键检查

1. 读取清单、锁、解析器/工具链版本及实际依赖图，区分直接和传递引入路径。

2. 核验官方公告、影响范围、触发条件及修复版本；存在依赖不等于已证明可利用。

3. 选择受支持的最小升级/约束，核对 API、ABI、最低工具链和构建插件兼容。

4. 使用仓库包管理器和确定性锁流程，保留无关解析并审查生成锁差异。

5. 验证解析、构建及受影响行为，按需覆盖序列化/运行时边界，并保留回滚制品或已知锁状态。

6. 报告证据、精确改动及未测组合；源、网络和策略失败应解释，而非悄悄放宽全局配置。

<a id="scope"></a>
## 边界与案例

适用场景：
- 核验传递依赖漏洞是否影响当前后端
- 最小化升级依赖和锁文件
- 保持声明工具链修复包问题
- 规划依赖回滚与兼容检查

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
