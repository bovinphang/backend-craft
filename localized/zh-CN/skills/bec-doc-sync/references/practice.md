# 后端文档同步

## 关键检查

1. 使用本地公共事实源方法，检查清单、处理器/校验器、契约源、schema、迁移及真实 CLI/任务定义。

2. 将每条事实变更映射到 README、API 参考、示例、环境/配置文档及升级说明。

3. 区分生成产物与手写源，修改源并运行已有生成器，而非手改生成结果掩盖漂移。

4. 依据证据描述默认、错误、权限语义及上线兼容和迁移前提，不暴露真实密钥。

5. 检查链接、示例命令、schema/契约一致性及必要本地化内容，保留有意义历史记录。

6. 交付事实→文档映射、生成差异、已执行检查及未决事实；只阅读的示例不能声称已运行。

<a id="scope"></a>
## 边界与案例

适用场景：
- 请求变更后同步后端 API 文档
- 将迁移和配置变更映射到发布说明
- 从真实源更新生成 OpenAPI
- 按仓库事实核对后端命令示例

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
