# Java 工程规范

## 关键检查

1. 读取声明的 JDK、构建文件、wrapper 和包分层，保持当前语言级别与依赖平台。

2. 将 HTTP 校验/DTO 映射放在适配层，用例放在应用边界，持久化映射遵循既有数据层。

3. 事务围绕实际一致性单元，而非任意 controller；明确回滚行为，不在本地事务中混入失控外部副作用。

4. 保留异常原因并遵循仓库约定，在边界转换领域错误，不使用 catch-all 吞错后返回成功。

5. 测试用例不变量、记录缺失、重复操作和仓储失败；隔离级别/回滚结论需要真实数据库测试。

6. 使用已有检查与离线准备好的构建工具；wrapper 分发和依赖准备是独立动作，未运行的检查如实报告。

## 边界与案例

适用场景：
- 分离 Java HTTP DTO 与持久化实体
- 审查 Java 模块应用事务边界
- 遵循现有 Maven 或 Gradle wrapper
- 为 Java 服务增加行为测试

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
