# 后端可观测性

## 关键检查

1. 从运维问题及服务目标出发，确定入口、依赖和存储层需要哪些信号。

2. 指标用于聚合，追踪用于请求因果路径，结构化日志用于有界事件细节；定义稳定关联字段。

3. 指标维度保持有界，采用路由模板/状态类别，而非用户 ID 或任意 URL。

4. 发出前脱敏凭据并最小化个人数据，设置保留/访问控制，不依赖报告读者事后删密钥。

5. 为采集开销、采样和导出失败设预算；诊断采集有时长/数量限制并遵循生产权限。

6. 用一次受控请求/失败验证关联及字段过滤；报告覆盖缺口，而非只统计日志数量。

## 边界与案例

适用场景：
- 关联后端追踪和数据库等待
- 控制指标基数及敏感字段
- 设计错误诊断的有界采样
- 端到端验证服务延迟与错误观测

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
