# 后端性能证据与优化

## 关键检查

1. 比较前固定负载、数据规模、并发、环境和测量方法，记录可重复基线及波动。

2. 分离服务时间、排队及下游等待，采集能区分 CPU、I/O、锁、分配和查询成本的证据。

3. 调整最小的已证实约束，保留正确性契约，尤其取消、授权和一致性。

4. 在重复等价负载下对照，观察错误、资源占用和尾延迟，而非只看平均耗时。

5. 定义饱和及回滚阈值，限制诊断负载，区分容量提升与瓶颈转移。

6. 交付基线、剖析/追踪证据、改动、实测效果及未验证条件；未测量就不编造提升比例。

<a id="scope"></a>
## 边界与案例

适用场景：
- 定位慢服务的实测瓶颈
- 在等价负载下比较后端 p99 变化
- 剖析数据库和 CPU 的延迟贡献
- 设置性能回归与回滚阈值

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
