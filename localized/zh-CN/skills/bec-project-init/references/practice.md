# 后端工程初始化

## 关键检查

1. 改上下文文件前先检查根及最近目录规则、清单和 CI 任务。

2. 识别项目根与任务局部语言，保留多项目结果，对原生语言/构建歧义作明确标记。

3. 提出最小相关规则引用，不把所有语言完整复制进全局指令文件。

4. 保留用户和前端上下文，使用产品片段或宿主支持的独立文件，初始化写入前展示拟改动。

5. 质量命令依据真实清单/任务和显式配置，分别报告缺失工具及集成环境要求。

6. 检查引用、作用域和配置结构，提供文件清单和剩余准备步骤；不自动安装编译器、数据库或依赖。

## 边界与案例

适用场景：
- 为前后端混合仓库初始化后端规则
- 保留 AGENTS 增加 Go 和 native 上下文
- 选择按语言作用域的验证配置
- 报告缺失工具链但不安装

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
