# 后端测试驱动流程

## 关键检查

1. 使用本地公共测试先行方法，选择一个可观察行为及能证明它的最窄测试层。

2. 写有意义失败预期，运行并确认失败来自缺失行为，而非语法、配置或缺编译器。

3. 实现最小改动，用同一测试转绿，再在相关套件保护下重构；保留真实命令和结果。

4. 并发用屏障及不变量断言，数据库原子性用合适真实集成，而不是恒成功 mock。

5. 已有代码时称为回归验证，在可行时重现旧缺陷，不编造过去先测后写的过程。

6. 工具/环境不可用时交付测试及明确未运行步骤；即使有截止压力，实际执行前证据仍为 NOT PROVEN。

## 边界与案例

适用场景：
- 修复前复现并发库存缺陷
- 以可观察红绿实现后端行为
- 用真实存储建立事务 TDD 回归
- 缺工具链时如实报告未运行

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
