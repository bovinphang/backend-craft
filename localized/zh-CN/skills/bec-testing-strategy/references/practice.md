# 后端测试策略

## 关键检查

1. 选择框架前列出业务不变量、信任边界、副作用及重要失败模式。

2. 单测验证局部决策，契约测验证生产/消费兼容，真实集成验证存储、隔离和资源行为。

3. 用可控事件覆盖重复投递、提交后超时、取消、并发和恢复，避免任意 sleep。

4. 以代表性系统旅程验证业务结果，不用昂贵端到端测试替代所有底层检查。

5. 定义夹具归属、隔离、清理及外部服务启用方式；mock 成功不证明数据库一致性或授权执行。

6. 交付风险→层次→证据矩阵，包含命令、实际结果和缺失环境；覆盖率不等于发布安全。

## 边界与案例

适用场景：
- 将后端付款风险映射到测试层
- 规划数据库回滚和重试集成测试
- 评估 API 兼容及失败路径覆盖
- 报告覆盖率之外的发布验证缺口

相邻专项应按实际任务选择；纯前端 UI、图片生成和普通文案润色不在此范围。

## 交付要求

- 已读取的工程/契约证据及变更作用域。
- 选用方案、关键不变量、资源/错误或失败边界。
- 实际运行的命令与结果，未运行项及不能证明的结论。
- 兼容、恢复/回滚或后续处理限制；评审结论须给可核实位置。
